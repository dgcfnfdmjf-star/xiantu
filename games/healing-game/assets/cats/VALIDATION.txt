=====================================

基线为用户已认可的 b18c3f8 四猫初版（从该提交的预览页提取内嵌 GLB）。
本次保留配色、花纹、坐姿与材质方向；21 个既有 V9.5 源码/构建文件的哈希
与修复前一致。抱猫、每毛色每程最多 4 次、20 点解锁、存档和其他关卡不变。

修复与预算
----------
减面后某些后脚/尾巴 UV 图块内部重叠，使尾巴条纹覆盖后脚；另有约 1 像素
采样偏移。现在拆分折叠图块、重新展开排列，使用 UV×贴图尺寸与像素中心
采样，烘焙原配色。构建检查重叠、退化和覆盖；导出 GLB 另经独立检查。
旧坏模型可检出 5,020 个冲突像素；最终四猫均为 0，退化 UV 三角面也为 0。
每只运行模型 6,886 三角面（原 35,280，减少约 80.5%），6 个模型绘制调用，
1 张 1024×1024 JPEG 内嵌贴图，无额外解码器。原高密度源网格、原 UV、材质
和原贴图保留在 .blend 隐藏源集合中；仅运行网格导出并用于 PNG 渲染。

----------

390×844 CSS 像素、DPR 2。每个版本每种网络各 3 次，共 18 次，交替测量。
每次新建浏览器上下文、禁用 HTTP 缓存、GLB 返回 no-store。计时从进入第二关
到当前请求的四种猫和装饰橘猫全部挂入场景；不包含初始 index.html 下载。
OS 文件缓存、Chromium 进程/GPU 缓存可能已预热。就绪时间包含解析、图片解码、
模型归一化与 JS 调度，不能视为独立的 GPU 上传或纯解码耗时。

场景渲染实测
------------
在同一空闲主机窗口重新测量初版、优化版及原代码猫。相同的 V9.5 页面用于
初版与优化版，文件哈希前后核验一致。固定场景种子、毛色顺序、大小与站位，
站位误差断言不超过 0.005 单位。猫停留原地；其他场景运动继续；朝向和精确
动画时刻未逐像素对齐。每场景预热 1.8 秒，再采样 5 秒。

帧间隔中位数 / p95（ms），n 为采样间隔数：
桌面 1200×900 DPR1，8 只活动猫：
  初版: 177.5 / 197.9, n=28
  优化版: 71.0 / 87.6, n=69
  原代码猫: 36.9 / 49.0, n=132
手机视口 390×844 DPR2，6 只活动猫：
  初版: 130.5 / 167.6, n=37
  优化版: 57.3 / 74.1, n=84
  原代码猫: 36.1 / 48.4, n=135
优化版相对高面数初版：手机视口中位帧耗时下降约 56%，桌面约 60%。
优化后的模型仍比简单代码猫更耗渲染资源。以上为云端软件渲染和手机视口模拟，
不是实体手机帧率；尚未验证真机稳定 30/60 FPS。
