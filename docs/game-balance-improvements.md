# 数值完善建议：成长与突破复核

复现：`node scripts/analyze-progression.cjs`。加载全部运行脚本，18 组境界/阶段公式探针，另调用真实 triggerBreakthrough(true) 验证成功、失败两条结算分支。仅替换结果面板渲染，保留结算逻辑；隔离模拟角色，无真实存档或付费请求。原始结果在 output/balance/progression.json。未修改生产数值。

## 已确认的结论

1. **暂不降低金丹修为需求。** computeRetreatV2782 的每日收益 = 当前阶段需求 / (360×10) × 修炼加成。因此无加成时，筑基和金丹从零修为闭关至满均理论需要十个游戏年。寿元、大比和已有修为会改变单次闭关时长。需求上涨不会同比拖慢闭关，但固定奖励的相对价值会下降，仍需区分战斗和闭关路径。
2. **突破概率实际生效，旧注释有误。** triggerBreakthrough 使用 Math.random()<rate，随后 settleBreakthroughV2781 调用成功或失败结算。筑基圆满模拟角色成功率 60%：随机值 .01 晋升金丹，随机值 .99 未晋升、384 修为降为 327、冷却 49 天。成功还会触发成就/任务奖励，不能把突破后剩余修为简单等同于突破前减门槛。
3. **后期连续失败是更明确的风险。** 默认角色保留未解心结 -15% 惩罚，清空丹药与装备加成时，大乘圆满及多个后期圆满阶段成功率触及 5% 下限。此为缺乏准备的受控场景，并非真实后期玩家的平均成功率。固定 5% 且独立尝试下，平均 20 次成功，至少成功一次达到 95% 概率需 59 次；不是保证第 59 次成功。
4. **失败代价叠加。** 失败损失当前门槛 15%（向下取整），生命变为上限 60%、灵力 50%，冷却 30–49 游戏日。无加成、无额外修为时补足 15% 约需 1.5 游戏年；5% 固定概率下，理论期望额外补修约 28.5 年。冷却与补修可能重叠，不能直接相加。渡劫圆满须走飞升天劫，已从普通突破期望计算排除。
5. **突破丹药路径待补齐核查。** 当前运行 JS 的名称搜索中，破障丹、九转金丹、渡劫丹仅在成功率函数出现；未找到明确购买/炼制/掉落定义。函数通过 inventory.includes 提供加成，未找到对应消耗。需明确它们究竟是消耗品还是永久持有效果，再补充来源与说明；不能把拥有三种丹药作为常规玩家基线。

## 建议实施顺序

| 优先级 | 完善内容 | 具体做法与验证 |
| --- | --- | --- |
| P1 | 突破信息一致 | 显示实际成功率、心结扣减、丹药/宗门加成、失败损失和冷却；统一使用结算公式，移除过时的自动晋升说明。先核对现有界面，避免重复添加。 |
| P1 | 后期失败保护 | 先补“当前瓶颈连续失败数”，不要复用累计 attemptCount；评估逐次加成或有限次数保底。按是否解除心结、宗门等级、可获得丹药比较期望/95分位尝试次数后定参数；成功换阶段清零，重载不清零，排除强制飞升。 |
| P1 | 突破准备途径 | 为实际可用的丹药明确来源、价格、加成、使用时机；若定义为消耗品，预览不扣、尝试扣一次、跳过动画/刷新不重复扣。避免无成本永久加成。 |
| P2 | 战斗与闭关收益协调 | 比较各境界实际可打怪物、可重复任务的修为占阶段需求比例。低阶任务不应随玩家境界无限放大；按任务/敌人难度分档，再考虑有上限的境界修正，防止刷弱怪成为最优解。 |
| P2 | 完整战斗与经济验证 | 使用真实可得装备与技能跑战斗，记录胜率、回合、耗蓝、恢复与药品花费；联查新手 8000 补助的实际支出后决定是否调整。当前单击探针不能作为怪物降强度依据。 |

建议先完善突破的准备途径、说明与失败保护，不整体砍低修为门槛，不统一削弱怪物。保底次数、增幅和丹药价格在对比模拟完成前均为待定参数。本轮未声称完成完整战斗胜率、全流程经济或真机体验验证。
