逐项核对及后续范围
1. 文本校验：确实拒绝姓名中的引号和 &，以及任意字符串中的尖括号。startGame 已调用校验器，并非完全无过滤。部分背包及其他界面仍拼接 innerHTML/onclick；直接改为只校验结构会移除现有注入防线。本轮保留规则。后续应先逐项迁移渲染和事件绑定，再放宽普通文字，并测试旧档及恶意导入。
2. 备份：仍是上一份有效主档的单备份，不是定时历史快照；无法防止持续保存后的逻辑污染。未擅自新增多份 localStorage 副本，以免增加容量失败。定时快照、突破前快照及容量淘汰需要一并设计。本轮只修复删除接口。
3. AI：源码已有 JEV_REQUIRE_SHARED_LIMITER 严格开关，README 已要求多实例生产开启；不能据此证明线上确实开启。没有检查或修改线上配置、预算或密钥。独立签名密钥、每日预算和同请求合并仍未实施。云函数 engines >=18 与根项目 >=22 不一致仍待单独升级验证。
   bootJevFriendsV2850 在未暂停时调用 ensureJevFriendSessionV2850；同页面有效 token 或 pending 请求会复用，页面重开不保留内存 token。票据不应视为强身份认证。
4. 错误提示：本轮修复，见上。
5. 迁移与映射：normalizePlayer 先调用 migrateCultivationV2793，再调用 migrateImmortalV2794，最终 schema 为4，不能只因中间写3就直接删迁移。当前扫描器 usesAlias 已识别别名后的点调用，包括 apply/call，旧报告需重跑核对。扫描仍是启发式，不证明死代码或真实执行路径。历史真实存档幂等性、name 类型及 hp 最终边界仍需专项审查；本轮未声称验证全部版本。
6. 死代码：暂未删除。直接覆盖不等于无用途，旧定义可能被别名闭包捕获；需结合调用链和加载顺序逐项确认。
7. 加载与 CI：本轮未改缓存、超时或重试。脚本加载超时后的重试涉及可能迟到的脚本执行，需避免重复初始化。测试清单是当前回归集合，QA 中含历史契约，不能直接将全部旧文件 glob 加入。新增本轮测试已显式接入 npm test。
