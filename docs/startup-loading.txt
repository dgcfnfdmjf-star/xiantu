仙途 V28.68.71：手机启动与开场流量优化

问题与范围
用户在手机 4G 下遇到样式加载失败，随后确认能正常进入、主要是等待较久。下载包内 CSS 已验证存在且版本正确，但当前开发环境不能访问该腾讯云域名，因此不宣称已确定线上那一次失败的根因。
对照启动流程发现：原入口在请求样式之前同时预取 40 个脚本；开场视频为 12,347,404 字节。此次处理资源优先级与开场流量，保留安全策略、存档和玩法。

实现
1. HTML 头部以高优先级预取样式和核心脚本。其余 39 个脚本等样式成功加载且版本校验通过后再并行预取，仍严格按照原有 40 脚本顺序执行。预取不会执行脚本，点击进入前实测已执行模块数为 0。
2. CSS 仍只下载一次；不会用内联样式绕过 CSP 或版本检查。样式错误/超时/版本不符会停止后续模块，保留原始报错。
3. 开场视频由 12,347,404 字节压到 5,556,202 字节（约 -55.0%）。保留 960×540、30fps、30 秒、H.264/AAC 与原画面顺序；moov 移到文件头（faststart），使用版本查询参数避免旧视频缓存。是有损压缩，细节会略柔化，非无损画质承诺。
4. 新增“跳过开场动画（记住选择）”，默认不勾选。勾选后点击进入不会设置视频 src，不请求视频、不播放；取消勾选可恢复开场。仅保存本机偏好 xiantu_skip_intro_v2898，不改角色存档；localStorage 不可用时，当次选择仍可用。保留手动跳过、静音/开声音、自动播放失败、8 秒停滞、45 秒总超时、离开页面的清理逻辑。
5. 40 个 build 标记、CSS token、入口/检测/预览缓存参数统一到 V28.68.71。Jev 代码与云函数包保持 V28.68.70；本次无需重传 Jev。

测量（本地受控环境，不是线上或真实 iPhone）
Chromium，390×844，冷缓存，150ms 延迟，下载 500,000 B/s（约4Mbps），上传125,000 B/s。服务器直接发送未压缩 JS/CSS，阻断外部请求，不调用真实 Jev。每组两次。
“脚本就绪”测量点击进入至40个脚本 build 标记齐全，不包含玩家选择看完30秒开场的时间。

默认看动画时，样式等待改善、视频更早播放，但脚本就绪在该样本中反而约慢0.52秒，因此不宣称所有场景总加载都更快。需要尽快进入游戏时使用可记忆的跳过选项；实测该选项没有任何视频资源请求。缓存、压缩、腾讯云响应和实际网络会改变结果。未核实线上是否启用 gzip/Brotli，不为此修改托管配置或添加 Service Worker。

视频检查
ffmpeg：libx264 medium，CRF27，maxrate1400k/bufsize2800k；AAC80k，faststart。
900帧对比SSIM All=0.936482；抽查12秒和24秒画面，保留主体、镜头及特效。该数值不是感知画质或物理手机播放保证。

验证
99项游戏回归脚本、20项安全/工具测试、4项打包测试、7项浏览器测试通过。
新回归覆盖样式失败时不启动模块、双击不重复启动、原40脚本执行顺序、视频所有退出路径、静音开关、保存/取消跳过偏好与存储拒绝。
浏览器额外验证：390px入口无裁切，偏好刷新后保留；勾选后进入成功且视频请求为0；取消后可播放新版960×540视频、开声音并手动跳过。现有浏览器测试保留版本不一致的失败保护，拦截在页面预取前安装。
