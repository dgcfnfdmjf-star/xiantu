# 装备升品与铭器继承

2026-10-14，基于 main `000c3f0`，参考用户提供的升品补丁实现。功能已接入项目代码；腾讯云部署需单独更新。

## 使用方式

从「角色装备」或「装备背包」进入「升品 / 继承」。每次只升级一件装备、一个品级，目标限定为同套装、同部位的下一档。支持当前新套装和青云、玄冰、天星旧套装的灵品至道器系列；最高档或无对应高阶版本的装备不会出现升品按钮。

- 有未锁定的同名高阶普通装备时，消耗一件作为胚子，不扣灵石。
- 没有可用胚子时，按现有商店价格补差价。锁定装备和加工过的铭器不会被当作胚子。
- 身上装备升品必须满足目标穿戴境界；背包装备可提前升品，仍需到境界才能穿戴。
- 铭器继承强化等级、当前词条和已付费但未选择的洗练结果；锁定状态跟随目标装备。普通同名装备只改变本次选中的一件。
- 页面展示消耗与继承信息，操作前确认。保存失败会恢复装备、胚子、灵石和铭器记录。

升品页使用完整的装备面板，避免长名称、词条和消耗被挤进剧情小窗。背包中同名普通装备合并显示数量，每次仍只升级一件。

## 成本与兼容

使用游戏真实的 `priceV2790`，没有另设价格表，也没有更改商店或现有高阶装备的属性。

| 升品 | 商店差价（灵石） |
| --- | ---: |
| 灵品 → 宝器 | 1,800 |
| 宝器 → 仙器 | 7,200 |
| 仙器 → 天器 | 28,800 |
| 天器 → 圣器 | 115,200 |
| 圣器 → 道器 | 460,800 |

铭器保留原记录中的强化、固定数值词条、百分比词条和待选结果，换成新底座后由原 `forgeRegisterV2825` 重新计算属性。新的铭器名称继续满足现有恢复器的前缀要求；同步替换装备引用和锁定引用，删除旧记录。无需新增存档字段，旧套装别名仍可升品。气血、灵力只按上限截断，不因升品自动补满。

每个页面的操作绑定角色、来源和确认前状态。离开页面、切换角色、换装、锁定胚子、灵石变化、进入战斗或突破后，旧操作不再扣费。重复点击和确认期间重入也被拦截。铭器编号分配会处理异常或极大计数，避免编号递增停滞。

升品目录在一次页面渲染中建立并复用，避免逐件反复扫描完整装备库。没有新增加载脚本，保持原 40 个脚本顺序。

## 验证

最终 50 组游戏回归、限流测试和 7 项浏览器回归全部通过。真实浏览器升品与重载记录见 `output/playwright/grade-upgrade/grade-browser.json`；手机界面截图为同目录的 `upgrade-phone.png`。

`QA/v286839-test-grade-upgrade.cjs` 纳入默认回归，覆盖：

- 190 个可升阶套装组合、同族同部位和实际差价。
- 一件替换、胚子位于来源前方、锁定胚子、铭器不能作胚子、原锁定状态保留。
- 灵石不足、取消、穿戴境界、背包提前升品、最高档与不支持的装备。
- 旧版固定数值和百分比词条、待选洗练、存档重载、继续选择词条、旧套装别名。
- 重复实例拒绝、旧页面/旧角色/战斗状态拒绝、确认期间状态变化与重入。
- 保存失败和铭器注册失败时完整回滚，不扣资源，不产生半成品，不自动回血回蓝。

真实 Chromium 使用临时角色从强化、洗练进入升品，消耗宝器胚子将灵品铭器提升为宝器，随后刷新页面并恢复存档核对记录；验证锁定胚子不会免除差价，及最高档不提供升级。360×800、390×844、844×390 使用触屏浏览器模拟检查，不等同于实体手机测试。批量验收的确认框由测试记录文本并选择确认；不使用真实存档，不调用付费 Jev。

运行 `node scripts/analyze-balance.cjs` 已取得 204 个既有公式探针的基线。实现没有调整旧装备、攻击公式或数值曲线。原始日志、重放脚本、前后截图保存在忽略目录 `output/playwright/grade-upgrade/`。
