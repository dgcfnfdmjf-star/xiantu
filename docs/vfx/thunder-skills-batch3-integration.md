# 雷系收尾四招实战接入

2026-10-16，基线 `df37ef9`。用户确认资源预览后，闪电链、万雷噬狱、雷神附体、九霄雷云接入原战斗、同台画卷与青云试剑坪。本批通过本地验收后，用户已授权上传 GitHub；未部署腾讯云，发布版本仍为 28.68.41。

## 行为与机制

| 技能 | 接入表现 | 保留的规则 |
| --- | --- | --- |
| 闪电链 | 单条电索、实际首击电结、散电 | 30 灵力、2.4 倍；单目标战斗不增加弹射 |
| 万雷噬狱 | 雷笼随真实雷域持续，每次实际结算产生一次电流脉冲 | 68 灵力、4.1 倍；原三回合雷伤池 |
| 雷神附体 | 雷铠跟随施法者；实际承伤触发独立反噬电梭 | 45 灵力、3 回合、雷伤 +35%、原实际承伤的 25% 反伤 |
| 九霄雷云 | 上方雷云与落雷；普通施法自行收尾，套装雷域成立才持续 | 55 灵力、3.8 倍、原法杖与套装限制 |

万雷噬狱与套装雷云继续共用原雷伤池，最后一次真实施加决定当前显示的域；不复制雷伤池，不增加 tick。附体独立占用一条状态记录。反噬不再重播施法动作，末次反噬可在雷铠回合归零后完成短动画。

核心只在真实施加、雷域结算、附体施加、反噬结算位置发送只读表现通知。固定 RNG 下，新旧核心的气血、灵力、金币、经验、回合状态、领域伤害、雷铠增益和随机数调用次数一致。未改存档格式、目标选择、控制、战斗定时器或 Jev。

## 资源与生命周期

新增 `xiantu-v2831-scroll/thunder-skills-batch3/`：20 张透明 PNG 帧条，合计 120 帧、2,096,395 字节；连同清单与资源预览共 27 个文件。原共享雷系素材保留，其四招路由迁至专用资源。完整源图、切片检查及过渡验收见 [资源制作记录](thunder-skills-batch3-resource-preview.md)。

`art/thunder-skills-batch3/state.js` 是表现状态控制器源文件；`sampler.js` 负责纯采样。`scripts/promote-thunder-skills-batch3-vfx.py` 同步资源和内嵌实现，备份原四个运行文件，并记录源与运行目录哈希。资源预览仍使用模拟事件，游戏从真实事件取值。采样器新增可选 `cloudHeight` 布局输入，未传时沿用已确认预览的高度；头像模式按 HUD 留白和左右空间调整高度、等比尺寸，避免裁边。

- 同台雷域锁定地面，雷铠跟随角色；没有从气血差或动画时钟猜测伤害事件。
- 背景停止绘制，返回后只恢复仍有效的状态，清掉历史脉冲，不重播起手。反复返回仅一个同台动画循环。
- 头像模式在窗口缩放、横竖屏、减少动态切换及敌方回击引发画布重建时保留真实状态，重新计算布局。
- 状态到期、换敌、换角色、死亡或退出会清理；退出释放同台事件订阅和画布。
- 减少动态保留静态状态轮廓；省电模式省略消散装饰。单张素材失败时用有界状态提示回退，不影响结算。
- 试剑坪加入套装雷云开关、雷域推进、承伤反噬与清除按钮。反噬从普通技能选择中移除，由承伤按钮触发。此页不读写正式存档。


## 绘制测量

同一台云端 Chromium 151 无头、DPR 1、自动画质、已预热试剑坪野狼、无灵宠，分别路由接入前备份和当前文件；每阶段采集 1.8 秒，实际绘制 27–46 帧。原始数据见 `output/playwright/thunder-batch3-integration/performance.json`。表中为 Canvas 绘制提交的 JavaScript 耗时，单位 ms：

| 视口 / 阶段 | 原版中位数 / p95 | 接入后中位数 / p95 |
| --- | --- | --- |
| 390×844 待机 | 0.3 / 0.5 | 0.4 / 0.4 |
| 390×844 施法 | 0.4 / 0.6 | 0.4 / 0.7 |
| 390×844 后续持续阶段 | 0.4 / 0.6 | 0.4 / 0.6 |
| 844×390 待机 | 0.4 / 1.6 | 0.4 / 0.6 |
| 844×390 施法 | 0.5 / 0.7 | 0.4 / 0.7 |
| 844×390 后续持续阶段 | 0.4 / 0.5 | 0.5 / 0.7 |

两版施法阶段实际绘制间隔中位数约 33.3–33.4 ms，待机与持续阶段约 66.7 ms，沿用场景原节拍。画布总像素分别为 381,520 / 681,220，接入前后不变。原版后续阶段没有持久雷笼；此测量展示新增表现的开销，不宣称性能提升。云端 CPU 测量不包含 GPU 时间，浏览器视口模拟不代表实体手机验证。
