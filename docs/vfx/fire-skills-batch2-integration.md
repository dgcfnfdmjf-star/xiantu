# 火系第二批 · 本地接入验收

2026-10-13。用户在资源预览后回复“记入”，按“接入”执行。红莲业火、火墙术、三昧真火已接入当前开发分支，未合并 main 或发布线上；版本仍为 V28.68.35。前批与既有太阳真火、冰蝶、焚心炎、绝对零度资源保留。

## 实现

批准的 13 张 PNG、清单与纯采样器复制到 `xiantu-v2831-scroll/fire-skills-batch2/`，逐文件核对哈希。嵌入配置和采样器由 `scripts/promote-fire-skills-batch2-vfx.py` 生成；预览说明文字改为已接入，PNG 和动画参数不变。渲染器复用第一批的按需缓存、正常 source-over 与缺图回退。

`xiantu-v2855-skill-fx.js` 新增 `fireBatch2` 接口，第一批 API 的定义列表仍保持三项。共用的资源准备和采样接口可以处理六招。红莲与火墙锁定目标脚线；三昧使用剑臂、移动主体与目标躯干锚点。命中取已有真实事件，未命中不会产生目标爆发。三招短表现保留到 1100ms，减少动态模式保留静态命中反馈。

`xiantu-v28684-duel.js` 只读传入 `burnHealBlock`。同一存活敌人满足灼烧次数、灼烧伤害均大于零且禁回生标志为真时，由现有灼烧表现所有者绘制小莲印，替代普通微焰。短红莲退场前不显示莲印；修复了命中交接第一帧提前闪印的问题。刷新灼烧保持当前循环相位，真实状态结束、死亡、换目标、隐藏及退出均按既有生命周期清理。没有新增 RAF 或战斗定时器。

试剑坪现有技能选择器可逐招播放，增加“清除灼烧 / 莲印”按钮。模拟状态只存在预览页中，不读取或写入玩家存档。

## 实战和回归

`QA/v286837-test-fire-batch2.cjs` 已加入默认测试：

- 图集惰性加载、末帧可达、未命中、资源失败回退、只读绘制和 RNG 不变。
- 真实装备施法，涵盖 0/1/3 次既有灼烧和两种固定随机数；开启/关闭绘制的战斗状态与随机调用一致。
- 原耗蓝 32/28/42、倍率 2.6/2.3/3.2、三昧基础穿防 40% 不变；灼烧分别 3/3/2 次主动出招，红莲禁妖元回生规则不变。
- 实际场景状态所有者：无提前莲印、短效果与状态不重复、灼烧结束/死亡/目标退出/后台恢复清理，无多余 RAF。

`npm test`：42 组游戏脚本及限流套件通过。`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser`：7 项通过。独立 sampler 的 36,000 次采样仍通过。

真实浏览器使用临时角色，通过 `combat('skill',0)` 分别施放三招。实测耗蓝 32/28/42，灼烧 3/3/2；只有红莲出现禁疗莲印，状态清除及死亡后停止绘制，重置后场景数为 0，无页面脚本错误。外部服务被阻断，不调用付费 Jev。

旧战斗 DOM 的减少动态模式显示红莲/火墙主体及三昧命中帧，均没有 RAF；清理后 active=0、raf=false、pixels=0。试剑坪检查通过技能选择、清除灼烧及换目标重置。手机模拟 390×844、DPR2 和横屏 844×390 无横向溢出。

实际命中峰值画面取自原场景绘制后的同一帧，不改战斗时间或伤害，见 `art/fire-skills-batch2/evidence/integration-peaks.jpg`。命中时点由实际事件决定，本次截图 H 在约333–433ms之间。
