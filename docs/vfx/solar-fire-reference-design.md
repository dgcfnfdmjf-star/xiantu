## 对照与设计

视频依次为掌前凝阳、圆形符阵、火球拖尾飞行、落点金色火柱与余烬。当前太阳真火共用火系飞焰，命中后加光环，缺少独有太阳主体。

保留现有立绘、水墨战场、88灵力消耗、5.3基础倍率与四次主动出招灼烧规则。仅改此技能的表现，不增加命中次数。原片不作为整段MP4遮盖战场播放。

| 阶段 | 画面与锚点 | 时间契约 |
| --- | --- | --- |
| 凝阳 | 施法者身前小太阳，细金色法阵向外展开 | 出手至现有命中点前，按命中时间的前35%分配 |
| 逐日 | 固定尺寸火球飞向目标；短尾焰跟随球体 | 命中前剩余65%，不拉伸球体代表运动 |
| 日焰爆发 | 目标脚下固定落点的短火柱与地面法阵 | 现有hit事件触发，跳字与爆发对齐；随后约180ms |
| 余烬 | 火柱快速散去，少量橙金余火；灼烧标识仍由状态系统负责 | 命中后180–540ms消散，受现有作业寿命约束 |

设计时间为相对窗口，具体帧数须资源预览验证。不能通过延迟实际伤害来让动画显得更慢。命中前不绘制爆发层，结束、逃跑、重置与隐藏页面必须清理。高亮仅用于窄金色火芯，主体保留橙金纹理，暗橙轮廓适应浅色纸面背景；血条和角色应仍可辨识。

参考草案中火柱的上端靠近边界；制作透明资源时必须保留安全边距并通过边界校验，不直接裁剪草案当精灵图。最终尺寸需在手机战场校准。轻量模式减少环数、余烬及拖尾，不减关键太阳主体。减少动态效果模式避免震屏和快速闪烁。

## 标准工作流与选择

1. Requirements analysis — already satisfied：已检查视频、原技能、命中和900ms表现作业。
2. Visual design — recommended：四阶段草案已输出，等待用户确认。
3. Asset production — blocked：依赖草案确认，再制作独立太阳材质母版及阶段帧。
4. Resource preview — blocked：依赖透明资源和安全边距校验，输出原背景对照。
5. Game integration — blocked：依赖已接受资源，接入现有事件和清理机制。
6. Test tooling — recommended：复用战斗预览入口，提供太阳真火独立播放。
7. Acceptance optimization — recommended：真实战斗、命中同步、轻量/减少动态效果、帧间隔和机制回归。

可选形式：`execute all`、`first N stages`、`specific stages`、`continue from stage N`。建议在接受这张草案后继续全部阶段。默认视觉设计与资源预览各需确认；用户明确要求不中断执行时跳过这两个确认停点。

本次采用标准模式。混合锚点（施法者、移动球体、目标地面）和严格命中同步是复杂点；可选多Agent模式能增加分层一致性复核，但也增加评审和证据整理成本。未获用户明确选择，不启用多Agent。
