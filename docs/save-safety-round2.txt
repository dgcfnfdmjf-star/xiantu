仙途存档安全优化（第二轮）
2026-10-21；源码基线 V28.68.50，未制作新发布包。

参考材料
用户提供的《仙途2.cjs》是依赖未附带补丁的测试草稿，不是可直接接入的补丁。
已参考其场景实现源码，并将适配后的测试纳入 npm test。

已落实
1. 读档先解析和运行真实 normalizePlayer 链，再重置运行态。
   主档迁移失败时继续尝试备用档；两者均失败则打开存档管理，不重置角色。
   初始化期间暂停 saveGame 写入，避免任务初始化立刻覆盖恢复候选档。
   读档失败不再排入新手引导的延迟初始化。
2. 导入、恢复备份及恢复上一位角色均先做完整预校验。
   检查成就数据结构；保留8MB、文本安全、异步读取角色归属、战斗及突破保护。
   校验失败不询问覆盖、不写存储、不重置运行态。
3. 导入及恢复备份前把当前实时进度存入独立的“替换前记录”槽。
   主档缺失且只有备用档时也可保全。仅一份，后续替换会更新它。
   上一位角色使用项目原有键 xiantu_save_previous_character，改为双向互换；离开的角色保留当前实时进度。
   localStorage 写入失败会回滚本次已写槽位；若回滚也失败明确报错，不声称浏览器存储具备跨键事务。
   空间不足停止替换并提示先导出，不提供“无备份强制覆盖”。
4. 原始导出不再被导入校验拦截；不合规则提示，但仍原样导出。
   手机在支持文件分享时可使用分享；取消分享不继续触发下载。
   普通下载报错时尝试剪贴板，仍失败则显示只读文本框供手动复制。
   新增复制当前存档、恢复/导出替换前记录入口。
   原始文本仅放入 textarea.value，不拼入 HTML；导入校验没有因此放宽。

测试稿的必要调整
- 修正“上一位角色”键，兼容真实旧档。
- 两次互换的断言检查实时进度；读档会补全默认字段与任务，不应要求与旧 JSON 字节完全相同。
- 存储满测试改为停止替换，不跳过留档。
- 加入异步读取期间换角色、成就结构错误、各槽位回滚、战斗收尾/突破保护、原始文本不执行等测试。
- 保留全部40模块加载，验证预校验不改变当前 player 引用、内容、全局键或存储。

验证
- npm test：64个游戏回归脚本、13项Node测试通过。
- Chromium既有浏览器回归：7项通过。
- 390px临时浏览器：存档面板可滚动、下载文件成功、导入合成角色并恢复替换前角色成功。
- 手机分享/取消、下载失败、剪贴板失败使用模拟分支测试，未声称实体手机分享面板实测。
- 浏览器可能静默忽略下载，无法可靠探测这种情况；可手动使用“复制当前存档文本”。
